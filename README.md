# 🔭 Справочник слабых сигналов (v3.0)

Сервис автоматизированного сбора и анализа **зарождающихся трендов (слабых сигналов)** в научно-технологических отраслях по авторской ТРИЗ-методологии.
Оператор вводит тему (например, «слабые сигналы в области кибербезопасности») и получает **ТОП-15 инсайтов на русском языке** с доказательной базой: стадия, динамика публикаций, патенты, фантастика, предикторы модели и ссылки на первоисточники.

(С) РуНео 2026

## Подробная инструкция

Пошаговый запуск (Windows без Docker, Docker, Linux/macOS, GitHub) и сценарий проверки в реальной работе — в файле [**INSTRUKCIYA\_ZAPUSK\_I\_PROVERKA.md**](INSTRUKCIYA_ZAPUSK_I_PROVERKA.md).

## Быстрый старт (Docker)

Требуется Docker Desktop / Docker Engine с Compose v2.

```bash
cp .env.example .env          # при необходимости впишите ключи API (необязательно)
docker compose up -d --build  # PostgreSQL + backend + frontend
```

* Интерфейс: [http://localhost:8080](http://localhost:8080)
* API (Swagger): [http://localhost:8000/docs](http://localhost:8000/docs)
* Проверка: `curl http://localhost:8000/api/health`

При первом открытии задайте пароль. Остановить: `docker compose down` (данные сохраняются в томе `pgdata`).

## Локальный запуск без Docker

Python 3.14.7 (проверено на Python 3.12; для запуска используется Python 3.14). Node.js нужен только для разработки интерфейса — собранный интерфейс уже лежит в `backend/static`.

* **Windows:** дважды щёлкните `START\_WINDOWS.bat` в корне проекта.
* **Linux / macOS:** `./start.sh`

Скрипт создаёт `.venv`, ставит зависимости, проверяет модель и запускает сервер; браузер открывается сам, **когда сервер уже отвечает**: [http://localhost:8000](http://localhost:8000) (запасной адрес [http://127.0.0.1:8000](http://127.0.0.1:8000); если порт 8000 занят другой программой, выбирается 8001, 8002… — адрес печатается в окне).

Вручную:

```bash
cd backend
python -m venv .venv \&\& source .venv/bin/activate      # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
python run.py                                           # http://localhost:8000
# PostgreSQL вместо SQLite:
# pip install -r requirements-postgres.txt
# export DATABASE\_URL=postgresql+psycopg2://radar:radar@localhost:5432/radar
```

Разработка интерфейса: `cd frontend \&\& npm install \&\& npm run dev` → [http://localhost:5173](http://localhost:5173) (запросы /api идут на backend :8000).

Тесты: `cd backend \&\& pytest -q`.

## Результаты проверки методологии

Датасет: 100 слабых сигналов (6 отраслей) + 132 контрольных примера хайпового фона (зрелые технологии, хайп, шум; 36 «трудных» в стиле датасета). Полный отчёт: [docs/dataset-validation-report.md](docs/dataset-validation-report.md).

|Проверка|Точность|
|-|-|
|Модель по методологии, повторная CV 10×5|99,4% ± 1,1 (F1 0,993)|
|Перенос на невиданную отрасль (leave-one-area-out)|99,6%|
|ТРИЗ-индекс **без обучения** (фиксированные веса методологии)|97,8%|
|Стресс-тест: невиданный «трудный» фон + отложенные сигналы|83,3% (recall 100%, precision 73%)|
|Наивный контроль «только стадия»|77,6%|

Цель ТЗ (не ниже 75–80%) выполнена во всех проверках. Оговорка: в датасете нет отрицательных примеров, поэтому фон подготовлен командой; стресс-тест показывает реалистичную нижнюю границу.

